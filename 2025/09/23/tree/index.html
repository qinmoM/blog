数据结构与算法（十）树

发表于2025-09-23|更新于2026-06-05|数据结构
|总字数:6.7k|阅读时长:28分钟|浏览量:

与链表类似，但是每个节点的地址域有两个或多个指向其他节点的指针。

相比其他数据结构：增，删，查平均时间复杂度快（均为O(log n)）。

二叉树：

————每个节点最多有两个子节点的树结构。

  • 层数(L)与元素个数(N)的关系：
    $$
    L = \log_2 N
    $$

功能分类：

BST树（Binary Search/Sort Tree 二叉搜索树）：

————用于快速查找，功能和二分搜索接近。

  • 性质
    对于任意一个节点，都有：左子节点 < 父节点 < 右子节点。
  • 实现
    1. 插入： 从根节点开始，按照小于向左找，大于向右找的方式找到第一个空节点，将节点挂在上面。
    2. 删除：
      这里要分三种情况：
      [1] 该节点没有孩子：直接将其删除。
      [2] 该节点有一个孩子：将该孩子挂载到父节点处，再将其父节点删除。
      [3] 该节点有两个孩子：将其变为第二种情况 : 用前驱节点或后继节点代替它（从该节点的左孩子开始向右找最大的，或右孩子向左找最小的），交换其数据，再将前驱（后继）节点进行1和2的操作，最后删除该节点。
    3. 遍历：
      也分三种情况，这里V是父节点，L是左节点，R是右节点：
      [1] 前序遍历：按照VLR的递归顺序遍历。
      [2] 中序遍历：按照LVR的递归顺序遍历。（得到的顺序是排好序的）
      [3] 后续遍历：按照LRV的递归顺序遍历。
  • 优点（相比其他树）
    代码实现简单。
  • 缺点（相比其他树）
    查询最慢，有序序列的储存会导致其退化为链表。

代码实现（循环 + 后继删除 + 中序遍历）

AVL树（Adelson-Velsky and Landis Tree 又名平衡二叉树）：

————为解决BST树失衡的问题，引入四种节点旋转操作。

  • 性质
    与BST树基本相同，但是经过处理之后，所有节点均未失衡（左右分支的高度差最多为一）。
  • 旋转理论
    1. 右旋
      当左孩子的左子树过高（高度差大于1）时，将该父节点的左孩子节点变为父节点，原父节点变为它的右孩子节点，原本左孩子的右孩子节点挂为原父节点的左孩子。
    2. 左旋
      当右孩子的右子树过高（高度差大于1）时，将该父节点的右孩子节点变为父节点，原父节点变为它的左孩子节点，原本右孩子的左孩子节点挂为原父节点的右孩子。
    3. 左平衡（左 - 右旋转）
      当左孩子的右子树过高（高度差大于1）时，先将其左孩子节点左旋，变为第一种情况后按照第一种情况右旋处理。
    4. 右平衡（右 - 左旋转）
      当右孩子的左子树过高（高度差大于1）时，先将其右孩子节点右旋，变为第二种情况后按照第二种情况左旋处理。
  • 优点（相比其他树）
    查询速度最快。（树的高度最均衡）
  • 缺点（相比其他树）
    1. 删除元素最差时间复杂度为 O(log n)，不是常数时间。
    2. 代码实现相对复杂。

代码实现（递归 + 前驱删除 + 中序遍历）

红黑树：

————通过颜色规则模拟平衡二叉树。

  • 性质
    包含BST二叉树性质。
    1. 每个节点必须有颜色，要么是红色，要么是黑色。
    2. 所有空节点nullptr是黑色。
    3. 根节点颜色为黑色。
    4. 不能出现连续的红色节点。
    5. 路径所有黑色节点数量一致（包括视为黑色的nullptr空节点）。
    6. 新增节点为红色（维护性质5）。
      总结下来就是一句话：左跟右，根叶黑，不红红，黑路同。
  • 实现
    1. 插入：
      [1] 检查是否为根节点，是根节点就染成黑色，不是则染成红色。
      [2] 检查父节点是否为黑色，是则插入成功；如果是红色，则肯定能确定其祖先节点（爷节点）是黑色（性质4）。此时剩下情况为：
      1. 叔叔节点为红色：此时将父节点和叔叔节点染成黑色，爷爷节点染成红色。之后再对爷爷节点从第[1]步操作。
      2. 叔叔节点为黑色：此时需要将父节点染黑，爷爷节点染红，再进行 AVL树的左旋（右旋）或左平衡（右平衡） 将父节点变为爷爷节点。
    2. 删除：
      判断待删除节点位置：
      [1] 如果是有两个孩子：找到其前驱（后继节点），覆盖待删除节点，再对前驱（后继）节点进行删除操作。
      [2] 如果只有一个孩子：此时可确定当前节点为黑色，孩子节点为红色（因为如果孩子节点为黑，一定会违反黑路同，所以孩子一定为红色；既然孩子为红色，那么当前节点一定为黑色，否则违反不红红）。此时删除节点只需要将孩子节点替换掉待删除节点，并且将孩子节点变黑。
      [3] 如果是叶子节点：判断此节点的颜色，如果为红色则直接删除；如果为黑色则判断：
      1. 兄弟节点为黑色：
        (1) 兄弟至少有一个红色孩子时：
        1. 如果父节点、兄弟节点、兄弟的孩子节点构成：兄弟的孩子节点相对兄弟节点、兄弟节点相对父节点，都为其左孩子（或都为右孩子）：将兄弟节点颜色变为父节点颜色，再将父节点和孩子节点都变黑；再对父节点做右旋（右孩子时为左旋）。
        2. 如果父节点、兄弟节点、兄弟的孩子节点构成：兄弟的孩子节点相对兄弟节点、兄弟节点相对父节点，一个为其左孩子，一个为其右孩子：将兄弟的孩子节点染成父节点的颜色，再将父节点染黑；再对父节点做：左-右时左平衡（右-左时右平衡）。
          (2) 兄弟的孩子节点都为黑色节点时：
          先将兄弟节点变为红色。（此时经过父节点的路径都缺少了一个黑色节点，所以进行以下操作）
          1. 如果此时父节点是为红色，则直接将父节点变黑，删除待删除节点后返回。
          2. 如果此时父节点为根节点，则直接删除待删除节点并返回。
          3. 如果父节点为黑色，则删除待删除节点后，需对父节点进行 删除[3] 的全部操作但不删除父节点。
      2. 兄弟节点为红色：
        ——此时父节点一定为黑色，因为要满足不红红。
        将父节点变为红色，兄弟变为黑色；再进行：兄弟为右节点时，对父节点进行左旋（兄弟为左时右旋）操作；再对待删除节点进行 删除[3] 的全部操作。
  • 优点（相比其他树）
    增删查最均衡的树结构，删除元素比AVL快很多。
  • 缺点（相比其他树）
    1. 查找元素比AVL树慢一点。
    2. 代码实现极其复杂，尤其是删除。

结构分类：

完全二叉树：

  • 最后一层的叶子节点是用靠左存储。
  • 介于结构的特殊性，普遍使用堆来实现。

堆（优先级队列）：

————逻辑上为完全二叉树。实际上用数组存储，用索引映射节点关系。

  • 实现：
    将0索引看作第一层（头节点），1和2索引看作第二层，3, 4, 5, 6看作第三层…以此类推。最后一层从左边开始数节点。
  • 注意：
    1. 两子节点的索引： 当前节点的索引记为 i ，左子节点索引为i * 2 + 1，右子节点为i * 2 + 2。
    2. 上一节点的索引： 当前节点的索引记为 i ，直接(i - 1) / 2。因为整型会向下取整，所以不用分辨左右节点。
    3. 由2可知：当元素数量为 n 时，所有有子节点的节点索引 i 的范围为：0<= i <= ( n - 1 ) / 2。
    4. 0位索引叫堆顶。
常见经典堆结构：
  • 大根堆（大顶堆）：
    1. 每个父节点都大于等于其左右节点的值。
    2. 所有父节点满足：arr[ i ] <= arr[2 * i + 1] && arr[ i ] <= arr[2 * i + 2]。
  • 小跟堆（小顶堆）：
    1. 每个父节点都小于等于其左右节点的值。
    2. 所有父节点满足：arr[ i ] >= arr[2 * i + 1] && arr[ i ] >= arr[2 * i + 2]。
堆的上浮与下沉调整（以大根堆示例）：
  • 上浮（入堆）：
    1. 先将元素放到数组最后位，即贴着二叉树最后一层节点的左边所有节点，层满就是下一层的第一位。
    2. 记录此时节点索引为 i ，计算上一位节点索引，让它与当前元素做比较，如果当前元素大，则将父节点元素赋值到此索引位置。
    3. 重复第二步，直到到达首节点或者当前元素比其父节点小，再将当前元素赋值到此索引位置。
  • 下沉（出堆）：只能出堆顶元素
    1. 记录并删除最后一位节点元素。
    2. 从堆顶开始：将当前元素与堆顶元素比较，如果当前元素大或二者相等，则将最后一位放到堆顶位置，记录此时索引0。
    3. 将当前索引的子节点进行比较，将较大的那个再与当前元素比较，若当前元素小，则记录较大的子节点索引，并将它赋值到父节点位置。
    4. 重复第三步，直到此节点没有子节点，或当前元素大于两个子节点元素，则将当前元素赋值到此节点。

复杂度分析：（入堆与出堆）
  • 时间复杂度： 平均O(log n)。最优O(1)，最差O(log n)。
  • 空间复杂度： O(1)。

多叉树：

————每个节点有多于两个子节点的树。

m阶表示一个节点有m个子节点。

B-树（名称为B树，并非B减树）

以m阶为例：每个节点有m个子分支，每个分支之间有一个元素，该元素左边的分支和元素都小于该分支，右侧同理。

树的高度更平衡，高度差为0。

  • 性质
    1. 平衡： 所有叶子节点在同一层。
    2. 有序： 每个节点内部元素都有序；任意元素左子树都小于它。
    3. 多路： m阶B树的节点：
      [1] 最多有m个分支，m - 1个元素。
      [2] 最少有m / 2（向上取整）个分支，m / 2 - 1（向上取整）个元素。(如果是根节点，则最少一个元素和两个分支)
  • 概念
    1. 上溢出： 节点元素数量超过m - 1。
    2. 下溢出： 节点元素数量小于m / 2 - 1（向上取整）。
    3. 失败节点： 空节点。（在查找时遇到空节点为没找到，所以叫空节点）
  • 实现
    1. 查找
      从根节点的第一个元素开始：
      [1] 向后对比节点每个元素，遇到大于该元素的就走该元素前面的分支，都小于则走最后元素后面的分支。
      [2] 重复[1]直到遇到失败节点表示无此元素。
    2. 插入
      [1] 进行查找操作，没有查找到，则需要插入；对查找到的位置进行操作：将元素插入到大于这个元素的前面。
      [2] 判断是否上溢出 ，是则进行分裂操作：找到该叶子节点的第m / 2 - 1（向上取整）个元素（后续称为目标元素），将节点分为：目标元素左边，目标元素，目标元素右边。将目标元素放到父节点的该指针位置，此时该元素左边和右边都为空的指针；将目标元素左边和右边重新作为新的节点，分别让父节点目标元素两边的指针指向。后续再对父节点进行[2]的判断上溢出操作。（如果是父节点发生了上溢出，则需要将上移后的节点作为新的根节点）
    3. 删除
      [1] 进行查找操作，查找到则需要删除。
      [2] 删除该元素，如果发生了下溢出，是则进行合并：判断相邻节点是否有大于m / 2 - 1（向上取整）元素数量的节点
      1. 两侧都为最少元素的节点：
        选择左边（右边）的节点作为相邻节点，将父节点中，指向 相邻节点 和 目标节点 中间的元素放到 相邻节点靠目标节点的元素位置，再将目标节点的元素放到相邻节点里即可；最后删除目标节点，并消除父节点的无用指针和元素位置。
      2. 有一侧的元素大于m / 2 - 1（向上取整）：
        将 该相邻节点最靠近下溢出的元素 与 父节点位于它两之间的元素，将它两的值交换，再将相邻节点对应位置的元素放到目标节点中靠近交换的相邻节点的位置。
        [3] 判断父节点是否下溢出，如果是，则进行[2]的操作。最后注意父节点的位置是否发生改变。

B+树

以m阶为例（与B-树相比）：每个节点有m个分支和元素，每个节点最后的元素记录父节点对应的元素，此操作可以保证叶子节点保留所有元素的同时，元素有序存储；此时再将每个叶子节点的尾部指向下一个叶子节点的头部。

所有元素都在叶子节点储存，上面只记录索引（关键字），叶子节点的关键字才记录对应数据。

解决了B-树的顺序访问只能用中序遍历的缺点，现在可以直接作为链表来遍历元素。

  • 实现
    1. 当一个节点满时，将节点按 1 / 2 分裂为两个节点。这样可以保证每次分裂只影响两个磁盘区块（父节点和此节点）。且不需要像 B* 树那样需要指向兄弟节点的指针。
  • 优点
    1. 顺序查找，范围查找都比B-树快。
    2. 叶子节点记录所有数据的模式更契合磁盘，有着更少的查找次数。
  • 场景
    MySql等数据库的首选结构。

B*树

————只做了解即可。

  • 性质（相比B+树）
    [1] 非根、非叶节点再加入指向兄弟节点的指针。
    [2] 并且规定非叶子节点关键字个数至少为 2 / 3 * M。可保证块的使用率最低为 2 / 3（代替B+树的1 / 2）
    [3] 当该节点满时：
    1. 兄弟节点未满：将一部分数据移动到兄弟节点中，并改变父节点，再将元素放入该节点。
    2. 兄弟节点满时：将该节点和兄弟节点各复制 1 / 3 的元素出来，形成一个新节点，最后调整父节点。
      所以：B*树比B+树分配新节点的概率要低，磁盘使用率更高（将最低使用率从 1 / 2 调整到了 2 / 3）。
