以下四种基础排序和三种进阶排序并称 “七大比较排序” 。
稳定性：相同的数字在排序前和排序后的前后关系不变。例如：对 5, 5 排序，排序后前面的5还在前面，后面的5还在后面，即为稳定。
log：这里未说明底数的log，均指以2为底的log。

基础排序：

冒泡排序：

————相邻元素两两比较并向后移动，每一次循环将最后一位数字的顺序排好。

  • 思路：
    从开头开始，与它后面的一位进行比较，将每次所得的更大(更小)的数放在后面，比较一次就向后移动一位。比较完一轮就再从开头开始，但是末尾已经排好，不进行比较。
  • 优点：
    稳定性高。
  • 缺点：
    交换次数太多。
  • 优化：
    当一次遍历之后没有交换元素，证明排序已经完成，直接跳出即可。

复杂度和稳定性分析：

  • 时间复杂度： 平均==O(n^2)==。最好O(n)，最坏O(n^2)。(所有n^2算法里效率最低的)
  • 空间复杂度： O(1)。
  • 稳定性： 稳定。

选择排序：

————每次循环从无序部分选出对应元素，放到有序元素的后面。

  • 思路：
    使用一个min变量记录每次循环遍历到的最小(最大)值的索引，循环结束后，将它与这次循环的第一位元素交换。此时已经把本轮第一位数字排序好了，再从它的下一位继续。
  • 优点：
    相比冒泡排序效率更高，因为每次遍历只做比较，不交换元素。
  • 缺点：
    但是比较次数太多。
  • 优化：
    无。(无法提前退出循环，如果要记录每次是否排序完成，则要在每次比较时增加最近两位元素的比较，反而会降低效率)

  • 空间复杂度： O(1)。
  • 稳定性： 不稳定。

插入排序：

————将元素逐个插入到有序部分的对于位置。

  • 思路：
    第一个元素是有序的，所以从第二个元素开始比。每次将当前元素，从有序部分的最后一个元素向前比较，大于(小于)对方就交换。
  • 优点：
    简单排序中效率最高。(==趋近有序==时为所有排序最快排序)
  • 缺点：
    越趋向于与排序后顺序相反的数组，排序效率低。
  • 优化：
    1. 当遇到不交换的情况时，可直接跳出内层循环。
    2. 由于内层循环要比较的值是固定的，所以只要用一个变量 key 存储当前值，向前找需要交换的元素时，直接让这个元素覆盖当前元素，直到满足条件或者索引为0，将 key 赋值给当前索引位置即可。

  • 时间复杂度： O(n^2)。最好O(n)，最坏O(n^2)。(效率远高于选择排序和冒泡排序)
  • 空间复杂度： O(1)。
  • 稳定性： 稳定。

希尔排序：

————插入排序的进阶。先从全局角度将数据调整为趋于有序的状态，再使用插入排序。（利用了插入排序的特性：当数据趋于有序，效率越高）

  • 思路：
    1. 对总数组进行分组处理，每组元素由原数组间隔一定距离组成。用一个gap变量记录分组间隔，从第一位开始到第gap - 1位为止，将数组中每间隔gap的元素组成size / gap个小组。
    2. 对每个小组插入排序。
    3. 将gap以一定方式减小，再从第2步进行，直到gap变为0或者排序完成为止。
  • 优点：
    效率可以比插入排序更高。
  • 缺点：
    不稳定。时间复杂度计算困难。
  • 优化：
    内层循环与插入排序相同。最外层可使用Hibbard、Sedgewick等算法优化。

快速排序：

————冒泡排序的进阶。虽然选择基准数，再与其他元素比较的方式很像选择排序，但是其本质是通过大量交换来实现，所以认为更像冒泡排序。

  • 思路：
    1. 每次选择基准数。
    2. 把小于(大于)基准数的放到基准数的左边，反之右边。
    3. 采用分治思想（对基准数左右边分别进行这样的处理）处理剩余序列，直到有序。
    4. 示例：（升序）
      46, 8, 76, 10, 38, 7, 68, 32, 65, 53
    5. 选择46作为基准数，再定义两个索引L和R分别指向开头和结尾。
    6. 从R开始向前找到第一个小于46的数，这里找到32，将32直接赋值到L位置（基准数已被记录），再让L++。
    7. 从L开始向后找到第一个大于46的数，这里找到76，将76直接赋值到R位置，再让R–。
    8. 重复2和3操作，直到L=R，将基准数46赋值到此处。此时46已完成排序：32, 8, 7, 10, 38, 46, 68, 76, 65, 53。
    9. 将数据以46为分界线分成两份：32, 8, 7, 10, 38和68, 76, 65, 53。
    10. 再分别对这两份进行1到5的操作，直到每边只剩一个元素。
    11. 解析：
      与二分搜索类似，可看作将数据划分为一个二叉树，故而也可以用递归实现。
      以上示例就可以看做是一个46为头节点的二叉树结构。
  • 优点：
    1. 平均性能是所有排序中最优。
    2. 缓存命中率高，数据访问跳度小，同时间复杂度下性能更优。
  • 缺点：
    1. 排序趋近有序的序列时效率较低。（可以用三数取中优化最坏时间）
    2. 空间占用较多。
    3. 数据类型要求：此数据类型的数据可以拷贝。
    4. 不稳定。
  • 优化：
    1. 对小段有序序列采用插入排序。
      因为随快速排序的进行中，数据是越来越有序的，并且在趋于有序的情况下插入排序效率最高，所以在begin到end序列小到一定数量（具体根据测试效果走，这里推荐32）时，直接让其采用插入排序。
    2. 三数取中。旨在挑选合适的基准数，防止退化为冒泡，但本身并不提高效率。
      对比R，L，mid(( R + L ) / 2)这三个索引位置的数，选择他的中位数，将其与首元素交换位置。
    3. 随机数法。
      更推荐三数取中法。

归并排序：

————以分治为主要思想进行排序。

  • 思路：
    先进行序列划分，再有序合并。归并：指用递归实现，在”归”的时候进行数据合”并”，合并的过程达到排序的目的。划分时可以划分为2段，即二路归并。
  • 优点：
    1. 稳定性强，高级排序里唯一的稳定排序。
    2. 时间复杂度稳定，无论最好还是最坏都是O(n log n)。
    3. 适合大数据和外部排序（磁盘中数据量大，数据无法全部拷贝到内存的情况）。
  • 缺点：
    空间占用太多。
  • 优化：
    1. 与快排相同，在小段序列使用插入排序来优化空间复杂度。
    2. 每次排序时都要开辟和释放数组，消耗大，可以在接口处直接初始化一个等长数组，再给每个小段传入它的引用。

外部排序：

  • 对于数据量大于计算资源的排序，可采用归并的外部排序解决。
  • 示例：100MB内存，排序1GB（1024MB）的数据。
    1. 创建11个文件，分别将数据输出到这些文件里，保证每个文件的数据量都可以放到内存中。
    2. 对每个文件进行原地排序（堆排序等）。
    3. 创建一定数量的文件，对其中两个排好序的文件各拿取一半数据，对这个数据排序并写入新文件中；再取剩余的一半，再写入这个文件。
    4. 每两个文件进行3的操作。（包括新处理好的文件）
    5. 最后写入的文件就是排好序的样子。
  • 根据上述可以发现，采用了归并的分治思想。

堆排序：

————选择排序的进阶。

  • 思路：
    ——通过大根堆和小根堆的优先级高先出的特性，先将数组调整为大(小)根堆，再一个一个出元素。
    1. 从最后一个非叶子节点开始进行上浮操作：对比它的子节点，找到最大(小)的那个，判断是否大于(小于)当前父节点，满足就做一次堆下沉；一个一个向前找，直到走到头节点。
    2. 出堆，并处理堆结构：输出交换最前最后两个元素，总元素个数减一(后续不管被交换的最后的元素)，将被交换到头节点的元素与其子节点的最大(小)元素相比，子节点更大(小)则将子节点写到父节点。再将此时的子节点更新为父节点，重复上述步骤，直到此节点是叶子节点或者比叶子节点都大，将原本最后一位节点的元素赋值到此节点位置。
    3. 此时便是与原本倒置的顺序：大根堆(升序)，小根堆(降序)。
  • 优点：
    1. 常量空间使用率。
    2. 时间复杂度稳定。
  • 缺点：
    1. 缓存命中率低，导致同时间复杂度下更耗费时间。
    2. 不稳定。
    3. 比较和交换次数较多。
  • 优化：
    1. 将每次比较的两个节点，从交换后再比较换成直接与原数据比较，找到位置后直接赋值。

计数排序：

  • 思路：
    1. 遍历一遍序列，找到最大元素。
    2. 创建一个count数组，大小为 找到的最大元素值+1，初始化值为0。
    3. 遍历序列，将每个元素当作新数组的索引，在对于位置++；
    4. 遍历新数组，将原序列覆盖。
  • 优点：
    效率极高，只有O(n + k)的时间复杂度。
  • 缺点：
    1. 数据类型限制极大，只对非负的整型有用。
    2. 需要新开辟数组，占用空间较大。

稳定版实现：

  • 思路：
    1. 让count不再记录每个索引的数量，记录每个索引最后位置的下标。
    2. count数组的实现：每个位置除了加对应数字的数量，还要加上上个索引的值。这样就记录了：这个序列在排好序之后，每个元素在排好的序列里，最后一个相同元素的索引。
    3. 倒着遍历序列，遍历的的元素的值，当作count数组的索引，查看这个位置上最后索引的位置。（之所以倒着遍历是因为count数组生成的时候会更方便）

桶排序（基数排序）：

————与上述七种非特殊排序并称”八大排序”。

桶排序：

————将数据分成多个区域，再对每个区域进行其他排序，是一种对其它排序的优化方案。

  • 思路：
    由多种不同的桶分布思路，比如：相同差值（在最小值和最大值之间，每隔一定数量分成多个桶）；以及先确定平均每桶的容量，再采用 桶数量 = (最大值 - 最小值) / 桶容量 + 1，元素对应桶的序号 = (元素值 - 最小值) / 桶容量。
  • 优点：
    1. 较灵活，可根据数组特性选择桶的性质，以及排序方式。
    2. 时间复杂度接近O(n)。
  • 缺点：
    1. 空间复杂度O(m + n)。
    2. 数据分布敏感，最坏时间复杂度能达到O(n^2)。

基数排序：

————对数据每一位进行排序。

  • 思路：
    1. 找到位数最长的数字，决定桶排序外层的次数。
    2. 由个位开始处理，把相应位数的数字放到相应序号（每次都是从0~9）的桶里，再按照桶的序号大小取出，放回原数组。
    3. 处理完所有位数，最终有序。
  • 优点：
    稳定性高。
  • 缺点：
    1. 数据类型限制大。
    2. 对超长位数数字排序效率下降明显。

示例问题：

关于STL标准库algorithm库的sort：

使用了什么排序？

  • 主体为快速排序。
  • 由于每次排序都可以让整个数组越来越有序，所以当划分的区域小到一定程度（通常为32）时，切换为插入排序。
  • 当递归过深时，切换为堆排序，防止溢出。

为什么没有归并排序？

  • 归并排序的特点是稳定以及适用外部排序，但是一般的排序不看重这些，其O(n)的空间复杂度也导致其并不实用。

如何实现当递归过深时，切换为堆排序？

  • 可以使用一个变量记录递归深度，当深度超过一定数值时（可以是取 log n 或者 * 0.75），切换为堆排序。
  • 示例：
    对1000000个数据排序时，期望递归深度是20层，但是最差是 n，也就是1000000层，所以排序时，先传入一个变量为元素个数，每次迭代这个变量，直到变量小于0（比如 * 0.75，最深为49层，之后就切换到堆排序）。

    基础排序的A, B, C排除；插入排序只有在趋于有序下最快，F排除；快速排序对于趋近有序的效率过低，D排除；故而选择E。

  2. 【2016阿里巴巴校招】 对1GB数据排序，但是计算资源只有1GB，最可能出现性能问题的排序是（）。
    A. 堆排序 B. 插入排序 C. 归并排序 D. 快速排序 E. 选择排序 F. 冒泡排序
    解析：
    内存和数据量接近最好原地排序，故而空间复杂度O(n)的归并排序最可能出现性能问题，故而选择C。

  3. 【京东】 只有100MB内存，对1GB数据排序，应该选择什么排序？（）
    A. 归并排序 B. 插入排序 C. 快速排序 D. 冒泡排序
    解析：
    对于数据量超过内存容纳的数据，只可通过归并的外部排序解决，故而选择A。
