多表查询

概念

业务逻辑

  • 业务中的表结构，经常分为三大类：

一对一

一对多（多对一）

多对多

基本用法

  • 对于多表查询( from 后加多张表时)，如果不加条件限定，会显示笛卡尔积(多个集合数量的乘积)数量条数据。

连接查询

内连接 inner

  • 查询A、B交集数据。只保留两表共有的数据。

外连接 outer

  • 以一个表作为基准，查询主表所有的数据（包括空）。不保留两表都为空的值。

自连接

  • 与自身连接查询。（必须使用表的别名）

联合查询

  • 对于列全部相同的查询，可以直接将结果拼接起来。

子查询 嵌套查询

概念

  • 子查询的外部语句可以是 insert / update / delete / select 。

返回结果分类

  • 标量子查询
    查询结果为单个的值。
    可以使用 =、>、<、>=、<=、<> 等运算符。
  • 列子查询
    查询的结果为一列。
    可以使用 in、not in、any、some（与any相同。子查询返回值满足一个即可）、all(所有值都必须满足) 等运算符。
  • 行子查询
    查询结果为一行。
    可以使用 =、<> 、in、not in等运算符。（对于多个值判断是否相等，可以使用 (字段列表) = (字段列表) 的形式）
  • 表子查询
    查询结果为多行多列。
    可以使用 in 运算符。

事务

  • 一组操作的集合。它们会统一向系统提交请求，要么同时成功要么同时失败。
  • 原理
    将一组操作整理为事务之后，开始执行事务时会标记开启事务，当最后没有发生异常时提交事务，发生了异常就回滚事务到开启事务。
  • 事务的操作
    1. 设置为手动提交（由于每一次执行sql语句，mysql都会自动提交操作，所以设置为手动提交后可避免只有部分操作执行成功了的情况）
  1. 事务操作
  • 事务的四大特性 acid
    1. 原子性 atomicity
      事务是不可分割单元，要么全部成功，要么全部失败。
    2. 一致性 consistency
      事务完成时，必须使所有数据保持一致的状态。
    3. 隔离性 isolation
      数据库系统提供的隔离机制，保证事务再不受外界并发操作而影响的独立环境下运行。
    4. 持久性 durability
      事务一旦提交或者回滚，对数据库的改变就是永久的。
  • 并发事务问题
    1. 脏读：一个事务读到另一个事务还没有提交的数据。
    2. 不可重复读：一个事务先后读取同一条记录，但是两次读取的数据不同。
    3. 幻读：按照条件查询数据时，没有对应的数据行，但是在插入数据时，有发现这行数据已经存在。
  • 事务隔离等级
    各等级，和其会出现的问题（等级越高安全越高，但性能越差）：
    1. read uncommitted :
      读未提交。表示会读取其他没commit的客户端修改到缓冲区的数据。
      脏读、不可重复读、幻读。
    2. read committed :
      读提交。表示不会读取缓冲区，只读取硬盘的数据。
      不可重复读、幻读。
    3. repeatable read（默认） :
      可重复读。表示其他客户端即使提交了数据，本地也只显示开始事务时的数据，但是在此等级下会出现其他客户端先增加数据后，本地明明查不到却显示不能添加重复键的提示。
      幻读。
    4. serializable :
      串行化。与repeatable read相同，但在本地开启事务后，会阻塞其他客户端插入数据，直到本地commit。
      无。
