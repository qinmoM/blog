Linux系统编程（七）系统调用（1）

发表于2025-11-25|更新于2026-06-08|Linux
|总字数:1.3k|阅读时长:4分钟|浏览量:

b站：io兄弟、满目星何x

概念

  • 系统调用：
    操作系统给用户提供的一系列特殊接口，通过他们来对内核操作。
    在逻辑上，属于内核于用户交互的中间人，不需要操作内核时不经过系统调用，调用了才会使用。
  • 实现：
    系统调用是操作系统的一部分，操作系统必须提供一种方式提供给进程调用。
  • 权限：
    运行在内核态的进程可以无限制访问资源，用户态则会受限。
    系统调用需要处于内核态。
    操作系统一般通过软件中断从用户态切换到内核态。

虚拟地址空间

每个进程都会被分配一个0-4GB的虚拟地址空间。逻辑上连续，但实际物理地址上是共享的，即虚拟地址片段随机映射到物理地址上。
进程中说的指针就是虚拟地址。
空间划分：

  • 用户区（0-3GB）低地址段
    受保护地址->.text代码段->其他段（制度数据段、符号段）->.data已初始化全局变量->.bss未初始化全局变量->堆空间（低地址向高地址）->共享库->栈空间（高地址向低地址）->命令行参数->环境变量
  • 内核区（0-1GB）高地址段
    内存管理，进程管理，设备驱动管理，VFS虚拟文件系统等…
    MMU
  • CPU中的硬件，将虚拟地址转换为物理地址。

系统调用和库函数的区别

linux对文件的操作有两种方式系统调用和库函数调用。
库函数由两种组成：

  • 不需要系统调用的：
    不需要切换到内核态。如strcpy、bzero
  • 需要系统调用的：
    封装了系统调用实现功能的函数。printf、fread
    流程：系统调用函数->系统调用接口（切换为内核态）->Linux内核->系统资源

c库IO函数工作流程

当调用c库的IO函数时：

  1. 使用fopen打开，创建并返回一个FILE结构体指针，结构体有三个内容：
    文件描述符（非负整数）：索引到磁盘文件。
    文件读写指针位置：指向缓冲区当前读写到的位置。
    IO缓冲区（内存地址）：指向缓冲区的指针。
  2. 执行写入操作时：
    先（根据文件读取指针位置）将数据写入到缓冲区，并将文件读取指针位置指针更新到最新位置；当主动fflush、缓冲区满了（默认8192byte）、正常关闭文件时，将数据写入到文件描述符。
  3. 执行读取操作时：
    根据IO缓冲区和文件读取指针位置判断缓冲区是否为空，为空就从文件描述符读取，文件描述符向后移动；读取后文件读取指针位置向后移动，直到为空。

c库错误处理

  • errno是记录系统最后一次错误代码，本质是int类型的全局，在errno.h查看。
  • 解析错误代码：
    1. 可以通过strerror(errno)解析当前的错误码，返回一个对应错误码的原因的字符串。
    2. 也可使用perror("提示");输出：提示:错误原因

文件描述符

概述

  • 对应Linux，所有对设备或文件的操作都是通过文件描述符进行的。
  • C库是用文件指针操作文件的，系统调用是使用的int非负整数。后续对文件的操作中通过该文件描述符，内核会记录这个打开文件的信息。
  • 当一个进程启动时，默认打开了三个文件：标准输入、标准输出、标准错误；对应的值是0、1、2，这些定义在unistd.h头文件中。
  • 文件指针和文件描述符可以相互转换：fileno将文件指针转为文件描述符，fdopen将文件描述符转换为文件指针。

详述

在每个进程的内核区中，存放着一个PCB进程控制块，它里面有一个指针指向文件描述符表（每个进程独有）。
文件描述符表：（文件描述符为下标）

  • 是一个指针数组，每个元素指向文件的元数据。
  • 数组默认大小为NR_OPEN_DEFAULT，也就是1024，也就是下标最多到1023，可以改动。
  • 文件描述符0，1，2默认为标准输入、标准输出、标准错误，且默认为打开状态。
  • 当再次打开一个文件时（比如打开一个hello.txt），会从里面选出最小的文件描述符。
    命令：
  • 查看当前系统运行打开的最大文件数：cat /proc/sys/fs/file-max
  • 查看默认最大打开数：ulimit -a
  • 设置默认最大打开数为4096：ulimit -n 4096

阻塞

  • 概念：
    进程在等待某类资源时，主动放弃CPU执行权并进入休眠状态的机制。
  • 当读取空管道、写入时已经写满、等待网络时，会出现阻塞的现象。
  • 阻塞是对文件而言的，与read，write等无关。
