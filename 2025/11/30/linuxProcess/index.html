进程和程序

  • 存储在硬盘中，没有运行的叫程序。程序是静态的。
  • 在内存中正在运行的叫进程。进程是动态的。

单道多道程序设计

单道

  • 进程一个一个排队执行，CPU空闲时即使A阻塞B也不会执行。

多道

  • 内存中同时存在相互独立的程序，在管理程序控制下，相互穿插执行。必须有硬件作为基础。
  • 时钟中段为多道程序的理论基础，在运行时进程不会放弃CPU资源，故而使用时钟强制停止。
  • CPU执行指令为纳秒级。

并行和并发

并行

同一时刻下，多条指令在多个处理器上同时运行。

并发

同一时刻下，只有一条指令执行，但是多个进程指令被快速切换，达到同时执行的效果。

MMU (memory management unit)

内存管理单元，作用有：

  • 虚拟地址映射为物理地址。
  • 管理虚拟存储器、物理存储器的控制路线。
  • 硬件机制的内存访问授权。
  • 多用户多进程。

进程控制块PCB

进程运行时，内核为每个进程分配一个PCB，维护进程相关信息。
需要了解的：

  • 进程id。每个系统唯一，c语言中用pid_t类型表示，是一个非负整除。
  • 进程状态。就绪、运行、挂起、停止等状态。
  • 进程切换时需要保存和恢复的CPU寄存器。恢复线程和保存线程。
  • 描述虚拟地址的空间信息。
  • 描述控制终端的信息。
  • 当前工作目录。
  • umask掩码。权限的掩码。
  • 文件描述符。包含很多指向file结构体的指针。
  • 信号相关信息。
  • 用户id和组id。
  • 会话和进程组。
  • 进程可使用的资源上限。

进程状态

概念

  • 进程状态反应进程指向过程，随着程序执行和外界变化而变。
  • 三态模型中：分为运行态、就绪态、阻塞态
  • 五态模型中：分为新建态、终止态、运行态、就绪态、阻塞态

流程

  • fork()创建进程。此时处于就绪态（TASK_RUNNABLE）。
  • CPU调度。变为运行态（TASK_RUNNING）。
  • 根据条件不同，会出现以下行为：
    1. 时间片到了，重新进入就绪态。
    2. 进程结束，但没有释放资源，此时为僵尸态（TASK_ZOMBIE）。
    3. 收到SIGSTOP和SIGTSTP信号，变为停止态（TASK_STOPPED），后续只能通过收到SIGCONT信号，进入就绪态后，再切换为运行态。
    4. 未申请到所需资源后，如果操作不能打断，则进入不可中断等待态（TASK_UNINTERRUPTIBLE），后续如果资源满足了就进入就绪态，再进入运行态。
    5. 未申请到所需资源后，如果操作能打断，则进入可中断等待态，满足资源 和 收到信号 进入就绪态，再进入运行态。

相关命令

ps

  • 查看进程的状态
  • 常用选项（可以不加-）：
    1. -a：查看终端上的所有进程，包括其他用户的。
    2. -u：显示进程的详细状态
    3. -x：显示没有控制终端的进程
    4. -w：显示加宽，以便显示更多信息
    5. -r：只显示运行的进程
  • 常用形式：
    1. ps aux：全部进程的详细状态
    2. ps ef：等价于ps aux

top

  • 在终端动态显示所有进程的信息，类似Windows的任务管理器。
  • 选项
    1. -d n：设置刷新间隔为n秒
    2. -u user：只显示user用户的
    3. -p PID：只看对应PID的
  • 按键（进入后只能使用按键操作）
    1. m：按内存排序
    2. p：按cpu排序
    3. t：按时间排序
    4. k：终止某个进程
    5. s：修改刷新时间
    6. q：退出
    7. h：查看帮助

kill

  • 杀死对应PID进程（PID通过ps查看）
  • 选项
    1. -9：强制终止

killall

  • 通过进程名字杀死所有同名进程
  • 选项
    1. -9：强制终止

进程号

  • 进程号 PID
    进程号是标识每个进程的，早期进程范围是0~32767的整数。
    进程号唯一，但是一个进程结束后，它的PID就可以给其他进程使用。
  • 父进程号 PPID
    任何进程（除了 init 进程）都是由另一个进程创建，此进程就是父进程。
  • 进程组号 PGID
    进程组是一个或多个进程的集合，用于接收同意终端的各种信号。默认情况下，当前进程号会作为进程组号。

等待子进程退出函数（回收资源）

wait

  • 进程退出时，有些特定资源不会被释放，主要指PCB的信息（进程号、退出状态、运行状态）。
  • 父进程可以调用wait和waitpid得到退出状态，并且彻底清除这个进程。
  • wait和waitpid的区别是：wait会阻塞，waitpid可设置不阻塞，还可以指定等待哪个子进程结束。
  • 一次wait或waitpid只能清理一个进程，清理多个进程需要循环。

解析子进程的宏

上述wait的status参数，就是作为以下宏函数的参数来用的。

  • WIFEXITED(status)
    非0表示正常结束，不正常则返回0。
  • WEXITSTATUS(status)
    得到退出状态码。（在正常退出使用，一般是子进程的exit里面的数字）
  • WIFSIGNALED(status)
    非0表示异常结束。
  • WIERMSIG(status)
    取得进程终止信号的那个编号。（一般在异常退出使用）
  • WIFSTOPPED(status)
    非0表示进程处于暂停。
  • WSTOPSIG(status)
    取得使进程暂停那个信号的编号。（一般在进程暂停后使用）
  • WIFCONTINUED(status)
    为真表示已经继续运行。（一般在进程暂停后使用）

关系父子进程

fork函数的代价非常大：

  • 继承：
    进程上下文，进程堆栈，打开的文件描述符，信号控制设置，进程优先级，进程组信号等。
  • 独有：
    进程号，计时器（小量信息）。
    为了节省资源，fork采用了写时拷贝，读时共享的特性。也就是说，只有进行写入操作时才会复制一份内容。

区分父子进程

父子进程地址

  • 栈区
    临时变量：读时共享，写时拷贝
    函数栈帧：完全独立
  • 堆区
    堆空间变量：读时共享，写时拷贝
  • BSS区
    未初始化全局变量：修改及拷贝
  • 数据区
    已初始化全局变量：修改及拷贝
  • 代码区
    程序指令：本身只读，永不拷贝
    注：
    因为堆空间也会拷贝，所以需要释放两次。（查看内存泄露的命令：valgrind ./a.out）

特殊进程状态

孤儿进程

  • 父进程结束，但子进程还在运行，此子进程就称为孤儿进程。
  • 每当出现一个孤儿进程，内核就会把它的父进程设置为init。（图形界面里可能不一样）
  • init进程会循环得wait已经退出的进程。
  • 因为有init进程，所以孤儿进程不会有什么危害。

僵尸进程

  • 子进程结束后，父进程未及时wait回收，会导致子进程在那一段时间里变成僵尸进程。
  • 由于父进程未结束，子进程不会被init接管去释放资源。
  • 有危害，应当避免。

进程替换

  • 如果原本运行着一个程序，想将它关闭启动另外一个，可以直接使用进程替换来完成。
  • 具体实现是由exec函数族完成的。
  • 会改变的内容：正文、数据、堆、栈。
  • 不会改变的内容：进程号，父进程号，工作目录。

函数名：

  • 带p（execlp，execvp）：表示第一个参数用文件名来指定文件，系统会依次去/user/bin，/bin，/user/local/bin找相同的文件名。
  • 不带p：表示第一个参数用绝对路径指定文件。
  • 带l：表示参数用list形式传递，即从第二个参数开始都是字符串。
  • 带v：表示参数用vector形式传递，即第二个参数是字符串数组。
    带e：表示自定义环境。
  • 注：
    1. 只有execve是系统调用，其他都是此基础上的封装。
    2. 所有的命令行参数必须以NULL结尾表示结束。

进程组

  • 也叫作业，表示一个或多个进程的集合，可以简化多个进程的管理。
  • 每个进程都属于一个进程组，waitpid和kill参数中都有使用。
  • 父进程创建子进程时，默认子进程为父进程属于相同id。包括组长，组中只要有一个成员存在，进程组就存在。

会话

  • 一个或多个进程组的集合。
  • 建立于控制终端会话的首进程称为控制进程。
  • 有控制终端的会话的进程组，分为一个前台进程组和几个后台进程组。
  • 终端接口检测到断开连接，会将挂断信号发给控制进程。

创建会话时注意事项

  • 调用的进程不能是进程组组长，否则会变成新会话的首进程。
  • 调用进程是组长进程时，会出错返回。
  • 需要root权限（ubuntu除外）。
  • 该进程会成为新进程的组长进程。
  • 新进程会丢弃原有的控制终端，该会话没有控制进程。
  • 创建会话时，需要先调用fork，父进程终止，子进程调用setsid。

守护进程 Daemon Process

概念

  • 也称为精灵进程，是Linux后台服务进程，一般生命周期较长。
  • 通常没有控制终端，并周期性得执行某项任务。
  • 一般名字以d结尾。
  • 周期进程是个特殊得孤儿进程，脱离了终端，不会被终端产生得信息打断，也不会显示任何信息。
  • Linux大多服务器就是用守护进程实现。比如：Internet服务器inetd，Web服务器httpd。

创建守护进程的模型

  1. 父进程fork一个子进程，父进程退出。（必须）
    父进程为组长进程，不能创建会话；且父进程与控制终端绑定，只能使用子进程。
    父进程退出后，子进程被init进程接管，脱离原来的进程组，不和终端绑定。
  2. 子进程中setsid()创建新会话。（必须）
    去除与原终端的联系，防止接收到其信号或终端关闭导致的进程阻塞或关闭。
  3. chdir("/")改变当前目录为根目录。（非必须）
    防止原来的目录被卸载。
  4. umask(0)重设文件掩码。（非必须）
    防止继承的文件创建屏蔽字拒绝某些权限。
  5. 关闭文件描述符。（非必须）
    防止 继承的文件描述符 在用不到的情况下 占用资源；且导致 文件 一直被占用 无法关闭。
  6. 开始执行守护进程核心工作。（必须）
    核心目的，注意做好退出处理。
