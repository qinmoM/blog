Linux系统编程（五）GCC

发表于2025-11-23|更新于2026-06-08|Linux
|总字数:1.6k|阅读时长:5分钟|浏览量:

b站：满目星何x

前言

  • 编译器
    将高级计算机语言翻译为低级机器语言的程序。
  • gcc
    原本为GNU开发的套件，现在已经被多出Unix系统采纳为标准编译器。

基础

基本格式

gcc/g++ [option] file …

  • 命令，选项，源文件之间用空格分割。
  • 一行命令可以有 0~多个 选项。
  • 文件名可以是绝对路径和相对路径。
  • 命令如果不包含可执行文件的文件名，Linux会默认为 a.out，Windows为 a.exe。

选项

  • -E : 预处理（去注释，宏替换，包含头文件）
  • -S : 编译（生成 . s 汇编文件）
  • -c : 汇编（将 . s 汇编文件生成 . o 二进制目标文件）
  • -o : 指定可执行文件的文件名
  • -g : 包含调试信息
  • -O0/O1/O2/Os/O3 : 大O优化，0不优化，3优化级别最高，s表示2.5
  • -Wall : 显示所有警告（包括低级别的）
  • -Werror : 表示有警告就不会编译通过
  • -D表达式 : 编译时定义宏，注意不要有空格
  • -I路径 （大写i）: 指定头文件目录。（不加空格）
  • -L路径 : 指定静态库目录。（不加空格）
  • -l库名 （小写L）: 指定静态库。
  • -shared : 生成动态库。

文件

  • .s : 汇编文件。（不互通，如x86汇编不能跑在AT&T下运行）
  • .o : 二进制目标文件。（使用file查看会出现LSB，表示小端模式）

静态库与动态库

静态链接和动态链接

  • 静态链接
    由链接器在链接时将库内容加入到可执行程序中。对运行环境依赖小。但是生成的程序较大，会占用更多资源；更新时需要重新编译。
  • 动态链接
    仅建立于所需库函数之间的链接关系，运行时才将资源调入。程序体积小；进程间资源共享；资源占用小。但是程序依赖动态库，并且版本问题严重。
  • Linux链接库时，默认会按照动态链接的方式。

静态库

制作

静态库在每个程序都会带有一份。因此，将两个静态库加载到内存时，如果他们都包含有一个 .o目标文件，这份 .o文件就会在内存中存在两份。

  • 将 .cpp文件预编译，编译，汇编 生成 .o目标文件。
  • ar工具：
    使用命令：ar -rcs 静态库名称 .o文件
    如果想将多个 .o文件 都编译成一个静态库，需要将所有 .o 都写入 -rcs 后面
  • 注意
    静态库命名需要采用lib + 库名 + .a来命名。

使用

  • gcc main.cpp -I头文件路径 -L库文件路径 -l库名

动态库

制作

在程序执行时常驻内存，可调用接口提前释放。

  • 生成目标文件，但是需要加入 -fpic 选项创建为 位置无关代码的 编译程序。（因为动态库会随机分配位置，不会像静态库那样固定位置）
    示例：gcc -fpic -c main.c
  • 使用-shared选项生成动态库
  • 注意
    nm 库名 ：可以查看接口。

使用

系统在加载动态库可执行代码时，需要知道库的名字，还需要知道路径。指定路径的方法如下：

  • （不推荐）将动态库放到标准库目录下，程序在找不到对应符号时会前往 /lib 文件夹寻找。
  • 使用动态载入器
    1. 临时设置（不影响其他终端）：
      export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:动态库路径
    2. 永久生效：
      在 bashrc 中添加 export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:动态库路径
    • vim ~/.bachrc
    • 在最后添加 export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:动态库路径
    • source ~/.bashrc（重新加载使其生效）
  • （不推荐）添加到 etc/ld.so.conf 文件中，再执行 sudo ldconfig -v
  • （不推荐）给 /lib 添加符号链接（一定是绝对路径）：sudo ln -s 动态库路径 /lib/lib库名.so

GDB调试器

GNU工具集的调试器是GDB，是一个交互式工具，工作在字符串模式。linux下有名的调试器还有xxgdb, ddd, kgdb, ups。

使用流程

  • 生成包含调试信息的程序：包含 -g 选项
    g++ -g main.cpp -o main
  • 启动gdb
    gdb 程序
  • （可选）设置、查看运行时参数
    set args / show args
  • 启动程序
    run：程序开始执行，有断点就停住。
    start：开始执行，执行一行。
  • 操作
    单步执行：next / n
    会进入函数体的单步执行：step / s
    退出进入的函数：finish / f
    执行到退出循环体：until / u [行数]
    全部执行：continue / c
    退出：quit / q

功能

  • 查看变量
    print / p 变量名
  • 显示源码
    list / l 打印源码：
    1. list / l ：默认10行
    2. list 行号 ：打印行上下文
    3. list function ：打印函数所在行上下文
    4. list - ：显示前面10行
    5. show listsize ：每次显示的行数
    6. set listsize 数字 ：设置每次显示的行数
  • 断点
    break / b 设置断点：
    1. break 行数 ：对应行数设置断点
    2. break function ：函数入口设置断点
    3. info/i break/b ：查看断点
    4. break 文件:行数 ：在对应文件的行数设置断点
    5. break 文件:行数 ：在对应文件的行数设置断点
    6. break class::函数 ：在对应类的函数设置断点
    7. break namespace::class::函数 ：在对应命名空间的类的函数设置断点
    8. break … if 条件 ：条件断点，满足条件时才停止
      delete / d 删除断点：
    9. delete ：删除所有断点
    10. delete 范围 ：删除指定范围断点
      disable / dis禁用，enable / ena生效断点：
    11. break 文件:行数 ：在对应文件的行数设置断点
    12. disable ：禁用所有断点
    13. disable 范围 ：禁用范围断点
    14. enable ：生效所有断点
    15. enable 范围 ：生效范围断点
  • 自动显示
    1. display 变量名 ：每步自动显示变量值
    2. info display ：显示所有自动显示信息
    3. undisplay 编号（info display时的编号） ：去除自动显示
    4. delete display 编号范围 ：去除一个范围内的自动显示（如：2-5）
    5. disable display 编号范围 ：使失效
    6. enable display 编号范围 ：使生效
  • 查看修改变量的值
    1. ptype 变量 ：查看变量类型
    2. p 变量 ：查看变量值

进程调试

调试进程时，gdb只能跟踪一个进程：（在执行到fork之前设置）

  • set follow-fork-mode child
    跟踪子进程
  • set follow-fork-mode parent
    跟踪父进程
