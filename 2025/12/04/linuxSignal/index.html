Linux系统编程（十一）信号

发表于2025-12-04|更新于2026-06-08|Linux
|总字数:2.9k|阅读时长:10分钟|浏览量:

b站：满目星何x

概述

  • 信号是一种程序中断方式，它是向进程发送的一个信息，来让这个进程进入信号处理某件事。
  • Linux早期的信号机制易丢失，Berkely和AT&T更改后有不兼容，所以POSIX.1对可靠信号列程做了标准化。

特点

  • 简单不能携带大量信息
  • 可以直接进行 内核进程 和 用户进程 的 交互
  • 满足条件才发送

信号周期

  • 信号产生
  • 在进程中注册和注销
  • 信号处理函数处理

信号四要素

通过man 7 signal命令可以查看信号的具体信息。
输入命令kill -l可查看全部信号的名称和编号。

  • 编号
    131号称为常规（普通、标准）信号，3464称为实时信号。
  • 名称
    不同系统下相同名称的作用相同，所以为了可移植性，通常会写名称来使用不同信号。
  • 事件
  • 默认处理动作
    man手册里五个常见默认行为：
    1. Term : 终止进程
    2. Ign : 忽略信号
    3. Core : 终止进程并生成Core文件
    4. Stop : 暂停进程
    5. Cont : 继续进程

示例

编号 信号 对应事件 默认动作
1 SIGHUP 用户退出shell时，该shell启动的所有进程将收到这个信号 终止进程
2 SIGINT <Ctrl+C>时，向用户终端中正在运行的程序发送这个信号 终止进程
3 SIGQUIT <Ctrl+\>时，会比<Ctrl+C>多生成调试文件 终止进程
4 SIGILL CPU检测到某进程执行了非法指令 终止进程并产生core文件
…
注：
SIGKILL和SIGSTOP是不可被捕捉，不可被忽略，不可被阻塞，保证了系统正常运行。

信号状态

产生

  • 按某些终端按键
    如ctrl+c发送SIGINT
    ctrl+\发送SIGQUIT
    ctrl+z发送SIGSTOP
  • 硬件异常（除数为0，非法访问内存等）
  • 软件异常（定时器alarm超时）
  • 调用系统函数（kill等）
  • 运行命令（kill等）

未绝状态

  • 信号没有被处理。信号处理函数未执行。

传递状态

  • 信号被处理了。
  • 由于信号的实现手段，导致它有很长的延时性。
  • PCB块里除了文件描述符，还有信号相关信息。

信号集

阻塞信号集

将一些信号加入屏蔽集合，如果收到屏蔽集合内的信号，则不处理，会收在阻塞信号集内。直到解除屏蔽后才会执行。

未决信号集

如果一些指令在接收到后没有立即执行（阻塞等原因），就是未决信号。
为了标记他们，在未决信号集中的该信号的位为变为1，直到被执行在标记为0。正常的信号也会有这样的行为，只不过变为1的时间非常短。

信号集

  • 阻塞信号集和未决信号集为PCB中两个重要信号集。
  • 是用位图机制实现。操作系统不允许我们直接用位操作，而是定义另外一个集合，借助信号集操作对PCB中两个信号集修改。
  • 信号阻塞流程：PCB块先前往未决信号集将对应位变为1，再检查阻塞信号集，为0则执行并将未决信号集对应位变为0，为1则阻塞，未决信号集里一直为1。
  • 阻塞信号集只读，不可修改；未决信号集可读可改。

sigprocmask

  • 阻塞信号集不会完全将信号移除，只是暂时禁止了它的执行。
  • 使用sigprocmask可以修改掩码来改变信号的阻塞情况。

sigpending

自定义信号集函数

信号集（sigset_t）是一个能表示多个信号的数据类型，可用于将一些信号批量处理。

信号捕捉

信号的处理方式

  • 执行系统默认动作
  • 忽略此信号
  • 执行自定义处理函数

信号捕捉处理流程

  1. 程序触发信号，将信号记录起来，等待程序中断时进入内核态。
  2. 因异常进入内核态，处理完异常后，检查是否有信号可处理，有则处理。
  3. 判断是否有自定义处理函数，有则返回用户态，执行自定义函数。
  4. 执行完自定义函数后，回到内核态，继续第2步检查。
  5. 直到处理完信号，恢复上下文信息等，回到main程序中执行。

signal

  • 该函数由ANSI定义，但由于历史原因，UNIX和Linux在不同版本下表现不一致，所以尽量用sigaction取代。
  • 配合定时器（信号SIGALRM）可以做到定时完成某些功能。

sigaction

  • sa_handler : 旧的信号处理函数指针，与signal里用法相同。
    sa_sigaction : 新的信号函数处理指针，多了信号来源，额外数据。需要配合sa_flags里的SA_SIGINFO使用。
    取值：
    1. SIG_IGN : 忽略该信号。
    2. SIG_DFL : 执行默认动作。
    3. 自定义信号处理函数。
  • sa_mask : 信号处理函数的过程中，屏蔽指定信号，防止处理信号时被其他信号打断。默认也会有当前处理的信号。
  • sa_flags :
    1. SA_RESTART : 让被信号打断的系统调用继续启动。（已弃用）
    2. SA_NOCLDSTOP : 使父进程在它的子进程运行时不会收到SIGCHLD信号。
    3. SA_NOCLDWAIT : 使父进程在子进程退出时不会收到SIGCHLD信号，并且子进程也不会变成僵尸进程。
    4. SA_NODEFER : 使信号的屏蔽无效，即在信号处理函数执行期间依然能发出这个信号。
    5. SA_RESETHAND : 重新设置为默认的处理方式。
    6. SA_SIGINFO : 使用sa_sigaction成员，不用sa_handler。
  • sa_restorer : 早期用来恢复上下文，现在弃用。

不可重入函数

满足以下条件的函数多数是不可重入函数：

  • 函数体内使用了静态数据结构。
  • 调用了malloc或free函数。
  • 函数体内调用了标准I/O函数。（子进程会继承父进程的缓冲区）
    可重入函数：
  • 写函数时使用局部变量（寄存器，栈中变量）。
  • 全局变量加以维护（关中断，信号量等互斥手段）。
    注：
  • 重新实现的信号处理函数必须为可重入函数。

SIGCHLD信号

产生条件

  • 子进程终止
  • 子进程收到SIGSTOP信号
  • 子进程处于停止态，接收SIGCONT后唤醒时

避免僵尸进程

  • 方法1 ：最直接的方式是wait等待，但会导致父进程挂起。
  • 方法2 ：通过SIGCHLD信号的信号处理函数释放。（内部要循环wait，防止有两个进程同时退出）
  • 方法3 ：使用signal函数的SIG_IGN通知内核去处理子进程的销毁。
