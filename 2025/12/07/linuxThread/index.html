Linux系统编程（十二）线程

概念

  • 线程是一个轻量级的进程，也有PCB，Linux下线程的本质依然是进程。
  • 进程是系统分配资源的最小单位：保存在硬盘空间，会在内存空间形成一个独立的个体，有自己的地址。操作系统以进程为单位分配资源。
  • 线程是系统调度的最小单位：进程的构成一定会包含线程的所有结构，即进程中最少有一个线程，或进程是线程的一个容器。
  • 线程是CPU委派任务的基本单位，本身基本不包含系统资源（除程序计数器、栈等）；它可以与同属一个进程的其他线程贡献全部资源。
  • 进程本身不进行调用，只做资源分配，调度的事情是交给内部的线程完成的。
  • 进程可以蜕变为线程。
  • 无论是创建进程的fork还是创建线程的thread_create，低层实现都是调用一个内核函数clone。复制对方的地址就是进程，共享对方的地址就是线程。

NPTL

  • native POSIX thread library。Linux线程的一个新实现，符合POSIX要求并且比LinuxThreads更具性能和稳定。

LWP

  • 用户级线程（NPTL）会绑定到LWP（内核轻量级进程）上，一个进程可以有多个LWP，最终线程调度器会把LWP和绑定到上面的用户级线程分配到CPU。

线程共享资源与非共享资源

共享资源

  • 文件描述符表
  • 信号的处理方式
  • 工作目录
  • 用户id和组id
  • 内存地址空间

非共享资源

  • 线程id
  • 处理器线程和栈指针（内核栈）
  • 独立的栈空间（用户空间栈）
  • errno变量
  • 信号屏蔽字
  • 调度优先级

优缺点

优点

  • 提高并发性
  • 开销小
  • 数据通信方便

缺点

  • 库函数不稳定
  • 调试困难，gdb不支持
  • 信号支持不友好

操作

线程号

  • 只在对应进程环境唯一。
  • 不同系统对pthread的实现不一样，做可移植的程序时不能把pthread_t当整形处理（如==判断等于）。

  • pthread_create的错误码不保存在errno中，支只能使用strerror把错误码转化为信息后打印。
  • arg可以传入共享静态变量或堆空间变量，但是栈变量不可以。

回收资源

注：

  • 与进程相同，不回收线程会导致线程变为僵尸线程。
  • 不可设置为非阻塞。
  • 终止状态分类：
    通过return等退出，retval中存放的是函数返回值。
    被别的线程调用pthread_cancel终止，存放的是常数PTHREAD_CANCELED。
    通过thread_exit自己结束的，存放的是它的参数。

线程分离

  • 线程可以设置为detach，在线程终止时立刻回收它的资源。
  • 处于detach的线程不能调用pthread_join，否则会返回EINVAL错误。
  • 线程依然依赖当前进程，只不过是将资源的回收工作给了系统来完成。
  • 函数不会阻塞。
  • 会随进程结束而结束。

线程退出

  • 不能通过exit退出。

线程取消

注：

  • 必须为同一个进程。
  • 线程取消是有延迟的，需要等线程达到某个取消点。
  • 取消点：通常是一些系统调用，create，open，read … 。执行 man 7 pthreads 可以查看具体列表。

  • 栈大小
  • …

注意

1>避免僵尸线程：

  • pthread_join
  • pthread_detach
  • pthread_create指定分离属性
    2>malloc和mmap的内存可以被其他线程释放。
    3>多线程模型下尽量不同fork，除非马上exec。
    4>避免在多线程中使用信号。
    5>若要让子线程不受其他线程退出影响，则主线程或其他线程中需要使用pthread_exit退出。

密集型

IO密集型

  • 指较多IO操作（阻塞），CPU较空闲。
  • 如：网络、文件、设备、数据库操作。
  • 推荐使用异步/事件驱动（epoll）。

CPU密集型

  • 较多CPU计算，CPU较忙。
  • 如：AI学习、图形渲染、视频编解码。
  • 推荐使用线程池，避免上下文切换。

注

  • 在单核情况下，不适用CPU密集型的程序，会多出额外的信息。
