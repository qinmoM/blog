网络编程（四）传输层协议

发表于2026-03-03|更新于2026-11-23|网络

传输方式

类型

  • 单播，都支持
  • 多播，ipv4可选，ipv6支持
  • 广播，ipv4支持，ipv6不支持
  • 任播，ipv4支持但不广使用，ipv6支持

广播

  • 注：广播千万不要 while 1 循环，由于广播地址自己也会收到，所以在网络层广播会直接返回，不经过链路层，导致即使拔掉网线也会一直发送。

特点

  • 同一子网所有主机都必须处理
  • 受限于局域网
  • 音视频等高速率运作会带来较大负担

地址

  • 定向广播地址：主机id全1，如xxx.xxx.xxx.255/24 …
    路由器通常不转发该地址。
  • 受限广播地址：255.255.255.255
    路由器从不转发该地址

多播

  • 对同一分组发送消息。
  • 分组表示为 特殊ip。

原理

  • 基于mac设备不完备硬件过滤，后再基于ip的完备软件过滤。
  • 每个主机只能将自己加入多播组。

特点

  • 多播地址标识一组接口
  • 可用于广域网
  • ipv4中，多播可选

地址

  • ipv4的D类地址为多播地址，如：224.0.0.1 …
  • mac地址前25位（mac前一半加一bit）固定为：01 00 5e + 0(1bit) 后23位为D类ip的后23位（省略前9位）

相关函数

UDP

  • 出错时不重传。（但是可以在实现上指定收到包后回复消息，否则重传）
  • 广播和多播只能用UDP。
  • 通常用于：DNS域名解析，NFS网络文件系统，RTP流媒体等。

步骤

UDP框架下本质无服务器和客户端区分，重点是看谁bind绑定了固定ip。
创建的套接字无端口和ip。

  • 创建套接字。socket
  • 服务器端绑定ip和端口。bind
  • 收发数据。sendto/recvfrom
  • 关闭。close

TCP

  • 出错时重传，每次发送数据对方都会回ACK。

步骤

客户端

  • 创建套接字。socket
  • 连接服务器。connect
  • 收发数据。write/read/send/recv
  • 关闭。close

服务器

  • 创建套接字。socket
  • 绑定端口ip。bind
  • 监听。listen
  • 提取一个客户端。accept
  • 收发数据。write/read/send/recv
  • 关闭。close

  • 注：
    每条SYN的报文都需一条ACK回应。
    给对方发送的确认号 = 上一条报文序列号 + 数据区长度（如果是SYN或FIN，此数据长度为1）
    本次序列号 = 上一次收到的确认号。

连接_三次握手

  • 调用connect触发。
  • 流程：
    1. 向对方发送：SYN为1，序列号为0，确认号为0，数据长度为0。同时将自己处于SYN_SENT状态。
    2. 对方发来：SYN、ACK为1，序列号为0，确认号为1，数据长度为0。对方处于SYN_RCVD状态
    3. 向对方发送：ACK为1，序列号为1，确认号为1，数据长度为0。将自己处于 ESTABLISHED 状态，connect 解开阻塞；对方收到后也会处于 ESTABLISHED 状态。

数据传输

断开_四次挥手

  • 应用层调用 close 触发，可以是服务器发起。
  • 流程
    1. 向对方发送：FIN为1，序列号设为m，确认号设为n，数据长度为0。自己处于 FIN_WAIT_1 状态；对方收到后处于 CLOSE_WAIT 状态。
    2. 对方发来：ACK为1，序列号为n，确认号为m + 1，数据长度为0。自己处于 FIN_WAIT_2 状态。
    3. 对方应用层收到 0 长度报文触发 close，发来：FIN为1，序列号为n，确认号为m + 1，数据长度为0。对方处于 LAST_ACK 状态；自己收到后处于 TIME_WAIT 状态。
    4. 向对方发送：ACK为1，序列号m + 1，确认号n + 1，数据长度为0。自己等待一段时间，如果对方发来FIN报文，说明没有收到ACK，此时重新发送ACK，直到一段时间内无回应；对方如果收到就结束，收不到就继续发送 3 报文。

SYN洪水攻击

  • 早期利用TCP三次握手缺陷攻击的手段。
  • 通过不断发送第一次握手，占满连接队列。

关闭

  • 为普通文件描述符关闭。
  • TCP中，close会向对方发送0长度报文表示断开连接。

绑定

  • 绑定自己的端口和地址。
  • 在未 bind 绑定时，第一次 sendto 会去随机绑定一个端口，后续不退出的话继续使用上一次端口。
  • 常在 udp 中使用。

连接

  • 绑定对方的端口和地址。
  • 会发生阻塞。
  • 调用connect时，底层发生三次握手。

监听

  • tcp服务器监听。

提取连接

  • tcp服务器提取一个完成连接，会阻塞。

收发

普通读写方式

  • connect 建立连接后可用普通文件读写方式。

携带地址信息

  • UDP使用，TCP建立连接后也可使用（不推荐）。

不携带地址信息

  • 必须调用 connect 后使用。
  • 相比sendto，send不能发送0长度报文
