B站：嵌入式-

tftp

  • 简单文件传输协议
  • 基于udp协议实现；不进行用户有效性认证。

传输模式

  • octet，二进制
  • netascll，文本模式

通信原理

  • 读写请求：
    2 byte 操作码(1读/2写) + n byte 文件名 + 1 byte ‘\0’ + n byte 模式(二进制/文本) + 1 byte ‘\0’ + n byte 选项1 + 1 byte ‘\0’ + n byte 值1 + 1 byte ‘\0’ + … + n byte 选项n + 1 byte ‘\0’ + n byte 值n + 1 byte ‘\0’
  • 数据包：
    2 byte 操作码(3) + 2 byte 块编号 + <=512 byte 数据
  • ACK包：
    2 byte 操作码(4) + 2 byte 块编号
  • 错误：
    2 byte 操作码(5) + 2 byte 差错码 + n byte 差错信息 + 1 byte ‘\0’
  • OACK：
    2 byte 操作码(6) + n byte 选项1 + 1 byte ‘\0’ + n byte 值1 + 1 byte ‘\0’ + … + n byte 选项n + 1 byte ‘\0’ + n byte 值n + 1 byte ‘\0’

选项

  • tsize：文件大小，读请求不需要写，服务器返回OACK时附带文件大小；写请求则需要发送自己的文件大小。
  • blksize：数据块大小（默认512），可修改为8~65464。
  • timeout：设置超时时间，秒为单位。

通信流程

客户端流程

  • 创建套接字。socket
  • 构建 读/写 请求报文。sendto / recvfrom
  • 打开要读取/写入的本地文件。open
  • 收发循环：
    1. 收：
      recvfrom 并记录字节数。
      服务器应答出错则退出。
      sendto 给服务器回应ACK。
      判断字节数是否小于 固定块512 + 操作码 2 + 块号 2 ，小于表示完成，退出循环。
    2. 发：
      sendto 给服务器发数据并记录字节数。
      recvfrom 服务器的ACK应答。
      服务器应答出错则退出。
      判断字节数是否小于 固定块512 + 操作码 2 + 块号 2 ，小于表示完成，退出循环。
  • 关闭。

示例

  • tftp格式—接收x.x.x.x服务器的69号端口管理的文件。

服务器流程

  • …

流程总结

  • 服务器在固定端口等待客户端请求。
  • 服务器批准请求时，会创建一个新线程使用临时端口通信。
  • 数据包的编号每次+1（从1开始：当请求使用选项时，服务器临时端口会回传一个OACK，此时回复的ACK需要 0 表示块编号未开始）
  • 每个数据包都需要得到ack回应，未收到则重新发送。
  • 长度以512传输。
  • 小于512表示传输完毕。

http

基于tcp的超文本传输协议。
用于浏览器与服务器的传递。

  • 支持c/s架构。
  • 简单快速：客户端向服务器请求时，只传送请求方式和路径，平时使用GET，PIST。
  • 无连接：限制每次只处理一个请求。
  • 无状态：如果后续要处理前面的信息，必须重新传导致每次连接传输的数据变大。

传输模式

  • 字节流传输。

通信原理

  • 客户端请求：
    method(GET / POST) + [空格] + 路径(/index.html) + [空格] + 版本(HTTP/1.1) + [\r\n]
    header(键 + [冒号] + [空格] + 值) + [\r\n]
    header(键 + [冒号] + [空格] + 值) + [\r\n]
    …
    [\r\n]
    body(数据)
  • 服务器回应：
    版本(HTTP/1.1) + 状态码(200 / 404) + 状态码描述(OK / Not Found)
    header(键 + [冒号] + [空格] + 值) + [\r\n]（Content-Length: 127）
    header(键 + [冒号] + [空格] + 值) + [\r\n]
    …
